   - Run the existing Stage-1 training CLI with `configs/extensions/intraday_ml/targets_mediummove.yaml` so the 120–240 min, ~0.8×ATR medium moves become the positive class.
   - Confirm the data loader finds SIP symbols (use the prebuilt `run/sip_membership` and the Gold bucket once the mount is healthy). Watch for the “Training dataset is empty” runtime error and fix the SIP membership/resolution if it reappears.

2. **Train the medium-move direction (Stage-2) model**
   - Reuse `train_bigmove_stage2_dir.py` with the medium-move target to capture directionality.

   - Execute `extensions.intraday_ml.experiments.score_mediummove_oos` pointing at `oos_features.parquet`/`oos_predictions.parquet` and the generated medium-move model bundle.
   - Inspect the resulting `artefacts/extensions/intraday_ml/phaseA_full_sip/oos_predictions_mediummove.parquet` for distributions of `prob_mediummove`, gap, expected R, and the hit rate with the current `mediummove_policy`.

   - Use `configs/extensions/intraday_ml/policy_config_mediummove.json` plus `configs/extensions/intraday_ml/policy_sweep_grid_medium.yaml` and `backtest_smoke.yaml` to run `policy_sweep`.
   - Target `mediummove_policy.probability_threshold` in the 0.01–0.05 band and track how many trades/day each configuration yields.
   - If trades/day remains below 3, relax the probability threshold and/or widen `prob_threshold_long` until you hit 3–5 trades/day without collapsing expected R.

5. **Phase-A OOS backtest with the new policy**
   - Update the Phase-A master config to consume the medium-move targets/policy and new `oos_predictions_mediummove` file.
   - Run `python run_phaseA_pipeline.py --config configs/extensions/intraday_ml/phaseA_sip_full.yaml` and examine `pilot_report.json`, `metrics.json`, and `trade_summary.*`.
   - Tune the medium-move policy `expected_r` floors, cooldown, and lifecycle windows if the realized R falls below 1.5 despite positive probability filtering.

6. **Validation checklist**
   - Re-run `pytest tests/extensions/intraday_ml` on the policy modules (`test_intraday_ml_decision_policy.py`, `test_risk_levels.py`) if the medium-move adapter touches shared logic.
   - Trace the new `mediummove_policy` entries in the rejection summary to ensure rejection reasons remain actionable.
